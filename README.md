# School Website

This repository contains a Ghanaian school website and admin CMS built with:

- React + Vite + TypeScript + Tailwind on the frontend
- PHP + MySQL on the backend
- Apache/XAMPP-friendly routing for the SPA, API, and uploads

## Included Features

- Public website with:
  - homepage sections driven by settings and CMS data
  - programmes, staff, gallery, and news pages
  - online admissions form
  - public contact/enquiry form
- Admin dashboard with CRUD for:
  - programmes
  - blog posts
  - staff
  - FAQs
  - facilities
  - testimonials
  - gallery items
  - enquiries
  - admissions
  - global site settings

## Local XAMPP Setup

1. Import `backend/database.sql` into MySQL.
2. Review `backend/config.php` and update the database credentials if needed.
3. Start Apache and MySQL in XAMPP.
4. Install frontend dependencies with `npm install`.
5. Run `npm run build` for the Apache-served build, or `npm run dev` for Vite development.

## Environment

For the standard XAMPP + Vite development flow, use:

```env
VITE_APP_BASE_PATH="/school-website"
VITE_API_BASE_URL="/backend"
VITE_DEV_API_PROXY_TARGET="http://localhost/school-website"
VITE_ALLOWED_EXTERNAL_HOSTS="facebook.com,instagram.com,twitter.com,x.com,youtube.com,youtu.be,linkedin.com,wa.me,whatsapp.com,google.com,maps.google.com"
```

The project can then be accessed at:

- Apache app: `http://localhost/school-website/`
- Vite dev app: `http://localhost:8080/`

Important:

- `VITE_API_BASE_URL` should stay as `/backend` for the normal Apache/Vite proxy flow.
- If the project is deployed into a different subfolder, update `VITE_APP_BASE_PATH` before building.

## First Admin Setup

This project no longer ships with a predictable default admin account.

After importing the schema on a fresh database:

1. Open the admin login page.
2. If there are zero admin users, the first-run bootstrap screen will appear.
3. Create your first admin username, display name, and password there.
4. Optionally add a recovery email during setup.

Important:

- Production installs should create the first admin through this bootstrap flow.
- The API will not silently recreate a default account anymore.
- Existing databases keep their current admins and can still use the local-auth upgrade migration safely.

## Account Recovery

- Admin accounts can now store a recovery email and generate a one-time recovery key from the Users screen.
- Recovery keys are shown once, should be stored offline, and are invalidated after use or rotation.
- The login screen includes a `Recover Access` mode for resetting a password with a valid username and recovery key.

## Uploads

- Uploaded media is stored in `uploads`.
- Ensure Apache can write to that directory and any nested folders created under it.
- Uploaded files are served from the same project under `/uploads/...`.
- Replacing or deleting CMS media-backed records now attempts safe cleanup of unused files, but shared file references are preserved.

## SEO and Public Files

- `robots.txt` and `sitemap.xml` are generated by the PHP entry point at runtime.
- The sitemap includes the homepage, programmes, careers, published blog posts, staff, gallery, and the admissions application page.
- There is no separate standalone `/contact` page by default; public contact access remains section-based on the homepage.
- Public pages now emit richer canonical, Open Graph, Twitter, and JSON-LD metadata for search engines and social sharing.

## Access Control

Role checks are enforced in the PHP API and mirrored in the React admin UI:

- `admin`
- `editor`
- `admissions_manager`
- `enquiries_manager`

## Notes

- The old Supabase setup is no longer the active backend architecture.
- Apache must have `mod_rewrite` enabled so the SPA, API, uploads, `robots.txt`, and `sitemap.xml` routes resolve correctly.
- In production behind HTTPS, keep PHP sessions on secure cookies and verify the host serves the app from the same base path used during the frontend build.
- For production CORS and safe link handling, set `APP_URL`, `ALLOWED_ORIGINS`, `ALLOWED_REDIRECT_HOSTS`, and `ALLOWED_EMBED_HOSTS` in the deployed environment or `backend/config.php`.

## InfinityFree Deployment

To prepare an InfinityFree deployment bundle, run:

```powershell
npm.cmd run deploy:infinityfree
```

This creates `deploy/infinityfree` with the same deployment-friendly structure used in `ghanaian-shepherd-main`:

- `backend/`
- `uploads/`
- `assets/`
- `index.html`
- `.htaccess`

Upload the contents of that folder into the InfinityFree `public_html` directory.
